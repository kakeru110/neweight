# コレクションページで「色が1つしか見えない」問題 — 原因と修正

作成: 2026-09-23 / 対象: Shopify `sumif_official` / テーマ Minimal

---

## 1. 何が起きていたか

コレクションページ（例 `/collections/rintintin`）の商品カードが、こうなっていた。

| 症状 | 具体例 |
|---|---|
| 商品名に色とサイズが付く | `RinTinTin Short Sleeve Tee（アダルト・ユニセックス） - オフホワイト / M` |
| リンクが1色に固定される | `/products/rintintin-short-sleeve-tee?variant=42091255693550` |
| 同じ商品が色違いで複数カードに分裂する | Brittany Spaniel キッズが オフホワイト/スミクロ/ピンク/グリーン の4カード |

お客さんから見ると「この商品はオフホワイトのMしかない」に見える。
実際は3色×2サイズある。**これが「カラー1つしか見えない」の正体。**

`/collections/all` では 20商品が **23カード**に膨らんでいた（3つは色違いの重複）。

---

## 2. 原因

`sections/collection-template.liquid` に、過去に入れた外部アプリ（`eosh-*`）の
「バリアントごとにカードを分ける」改造が残っていた。

```liquid
{% assign showVariantsIds = "436908726028624209073841790242091435065582…" %}

{% for product in collection.products %}
  {% for variant in product.variants %}
    {% if showVariantsIds contains variant.id %}
      {% include "eosh-product-grid-item-variants" %}   ← 色ごとのカードを出す
    {% else %}
      {% include "product-grid-item" %}
      {% break %}
    {% endunless %}
  {% endfor %}
{% endfor %}
```

`showVariantsIds` は**バリアントIDを区切り文字なしで1本につなげた数字の羅列**で、
それに対して `contains`（＝単なる部分一致）で判定している。

たとえば `42091255693550` という数字列がこの巨大文字列のどこかに偶然含まれていれば、
**そのバリアントは「色別カードを出す対象」として誤検出される。**
意図した商品だけでなく、無関係な商品まで巻き込まれていた。

アプリ自体はもう動いていない（後述）。**残骸だけが表示を壊していた。**

---

## 3. 修正内容

素のMinimalの挙動（1商品＝1カード）に戻した。

```liquid
{% for product in collection.products %}
  {% assign featured = product %}
  <div class="grid__item {{ grid_item_width }}">
    {% include 'product-grid-item' %}
  </div>
{% else %}
  …（商品が0件のときの表示。従来どおり）
{% endfor %}
```

### 修正結果（プレビューで確認済み）

| コレクション | 修正前 | 修正後 |
|---|---|---|
| RinTinTin | 3カード（うち1つが「- オフホワイト / M」付き） | 3カード・商品名のみ |
| British Dogs | 7カード（重複あり） | 6カード・商品名のみ |
| Brittany Spaniel | 6カード（キッズが4色に分裂） | 3カード・商品名のみ |
| All Items | 23カード | 20カード（＝実際の公開商品数） |

Liquidエラーなし。商品ページ・検索・トップページは元から影響を受けていない（確認済み）。

## 5. 調べて分かった他のこと

### 5.1 商品ページは元から正常だった

以前「商品ページですら色が選べる形になっていない」と報告したが、**これは誤りだった。**
JavaScript実行前のHTMLだけを見て判断していた。

実際にブラウザで描画して確認したところ、商品ページは

- `色` ： オフホワイト / スミクロ / ピンク
- `サイズ` ： M / L

の**2つのプルダウンに分かれている**。
Minimalは素のHTMLでは全組み合わせの `<select>` を1つ出し、
Shopify標準の `option_selection.js` が読み込まれた時点で色・サイズに分割する作りになっている。

→ **商品ページ側に直すところはない。**

### 5.2 「テーマ設定でセレクタを分割できる」も誤りだった

そんな設定項目は Minimal に存在しない。探させてしまい申し訳ない。

**ただし実在する設定が1つある**（テーマのコードを読んで確認済み）:

> オンラインストア → テーマ → カスタマイズ → **商品ページ** →
> 「**バリエーションピッカーとボタンサイズ**」

現在 **「小」**。ここを **「大」** にすると、色・サイズのプルダウンと
「カートに追加する」ボタンが横幅いっぱいになる。

いまは色のプルダウンが小さく、**選択できる箱に見えない**。
これも「色が1つしかない」と誤解される一因になっている。
クリック1回で変わるので、テーマ公開のついでに変えるのがよい。
（設定ファイル `config/settings_data.json` は21KBあり、全文の書き戻しは事故のリスクが高いため、
ここは管理画面で操作することにした。）

### 5.3 色チップ（スウォッチ）アプリは入っているが動いていない

テーマに **Globo Color Swatch** の設定が残っている。

- コレクションページ・商品ページとも「有効」
- `色` オプションに5色すべてが登録済み（オフホワイト `#f8f7ed` など**色コードも入っている**）
- 描画用のJSファイル（135KB）もテーマ内に存在する

しかし、描画を開始する条件になっている `window.GloboSwatchWorkingOnThisPage` を
セットするコードがページのどこにもない。
**アプリ本体がアンインストールされ、テーマ内のファイルだけが取り残された状態。**

→ 色チップを出したいなら、
　**(a)** Globo Color Swatch を入れ直す（設定は残っているのでほぼそのまま復活する見込み）か、
　**(b)** 色チップを標準で持つテーマ（Dawn / Sense 等）に乗り換える。

在庫を売り切るフェーズなので、**(a) のほうが速くて安い。**

### 5.4 テーマに残っている他のアプリ残骸

削除はしていないが、記録として残す。

| ファイル群 | アプリ | 状態 |
|---|---|---|
| `globo.swatch.*`（計約45万バイト） | Globo Color Swatch | 設定は生きているが描画されない |
| `eosh-product-grid-item-variants.liquid` `eosh-search-result-variants.liquid` | バリアント分割アプリ | **今回の不具合の原因。参照を外した** |
| `bss-product-label-js.js`（452KB）ほか | BSS Product Labels | 要確認 |
| `productwiz-rio.min.js`（540KB） | ProductWiz | 要確認 |
| `tms-translator.js`（275KB） | 翻訳アプリ | 要確認 |
| `booster-seo.liquid`（42KB） | Booster SEO | 要確認 |
| `collection-template-bk.liquid` | 改造前の原本 | 未使用 |

**合計で1.5MB以上のJSを毎ページ読み込んでいる。**
使っていないものを外せば表示が速くなる。ただし「どれが生きているか」の確認が先。
