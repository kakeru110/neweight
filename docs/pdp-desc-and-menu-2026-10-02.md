### サイズ表

原因は**テーマの `.rte table` が `width:100%`** だったこと。
4列しかない表が商品説明の幅（PCで625px）いっぱいに引き伸ばされ、
セルの中がスカスカになっていた。

- 幅を内容に合わせる（`width:auto`）→ **PCで625px → 193px**
- 縦罫を全部消し、横罫だけの表に
- 見出し行は小さい字＋字間を空けてグレー、下に黒い罫線
- 数字は `tabular-nums` で桁をそろえる
- サイズ名（M/L）は太字
- 愛犬用は列が多い（首回り・胴回り・体重目安）ので、
  スマホで入りきらないときだけ横スクロールする

セレクタは `.rte.product-description table`。テーマ既定の `.rte table` と
詳細度が同点だと読み込み順に左右されるため、1つ上げてある。

**23商品すべてに効く**（説明文を1件ずつ書き直していない）。

### 説明文末尾のリンク

テーマ既定だと下線も色も付かず、ただの文字に見えていた。

- 下線（`text-underline-offset: 4px`）
- 末尾の段落の上に罫線を1本入れて本文から切り離す

## ⚠️ メニューを一度壊した（復旧済み）

**シリーズ名を変えるときの `menuUpdate` で、メインメニューのリンクを全部壊した。**

`type: HTTP, url: "/collections/all"` のように相対パスを渡したところ、
Shopifyがこれを絶対URLとして解釈し、**`http://all` に書き換えた**。
`/collections/adult` → `http://adult`、`/policies/shipping-policy` → `http://shipping-policy`。
ナビ・フッターの内部リンクが全滅した。

**気づくのが遅れた原因**: `menuUpdate` のレスポンスで `title` しか返さず、
`url` を確認しなかった。タイトルは正しく見えていたので成功と判断した。
フッターを同じやり方で更新したときに `url` を返して初めて気づいた。

### 直し方

相対パスを `HTTP` で渡さず、**リソース型で指定する**:

| 行き先 | type | 指定 |
|---|---|---|
| コレクション | `COLLECTION` | `resourceId: gid://shopify/Collection/...` |
| ページ | `PAGE` | `resourceId: gid://shopify/Page/...` |
| ポリシー | `SHOP_POLICY` | `resourceId: gid://shopify/ShopPolicy/...` |
| トップ | `FRONTPAGE` | url不要（`url:"/"` はエラー「対象を入力してください」） |
| 外部URL | `HTTP` | 絶対URLのみ。相対パスは壊れる |

ハンドルが日本語のページ（`/pages/著作権について`）も `HTTP` では
`Not a valid URI` で弾かれるので `PAGE` + resourceId を使う。

### 復旧の確認

トップからナビ・フッターの全リンクを実際に踏んで確認:
**内部リンク29本すべて 200**。
失敗4件はTwitter/Facebook/Pinterest/Instagramで、
このコンテナから外部SNSへ出られないだけ（サイト側の問題ではない）。

**今後 `menuUpdate` を使うときは、必ずレスポンスで `url` を返して確認すること。**

タイル名が「大人」でその下にも「大人」と出て、同じ言葉が2回並んでいた。

→ **タイル名と同じ文字列になるときは出さない**ようにした。
