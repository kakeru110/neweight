# B（色ごとにカードを分割）の実装

開始: 2026-09-30 / 対象: Shopify `sumif_official`

ユーザー判断: 「色ごとに並べた方が見やすい。商品も多く見える」→ **Bで確定。**

---

## 1. 設計

23商品 → **48カード**（色ごとに1枚）。

| 区分 | 商品数 | カード数 |
|---|---:|---:|
| 2色以上 | 14 | 40 |
| 1色のみ | 6 | 6 |
| 色オプションなし（Various dogs） | 3 | 3 |
| 完売色（British Dogs 長袖Tee 大人 スミクロ） | − | **−1（出さない）** |
| **合計** | 23 | **48** |

### 完売色を出さない判断

British Dogs 長袖Tee 大人 スミクロ は OpenLogi在庫 M=0 / L=0 の完売。
売り切りフェーズで棚が狭いので、**買えないカードに枠を使わない。**
（商品ページ側では色チップに斜線を出して「あったが終わった」ことは伝える）

在庫僅少だが購入可能な色は出す。例: Flanders 長袖Tee 大人 スミクロ（M=1 / L=0）。

## 2. カード画像の作り方

カードは `variant.featured_image` を使う。よって**色バリエーションに着用写真を割り当てる**必要がある。

### 色の自動分類は断念した

胴体の色をサンプリングして色名に寄せる方式を2通り試したが、どちらも実用にならなかった。

| 試した方式 | 失敗の理由 |
|---|---|
| 帯の中央値 | 髪・デニム・影が混ざり、ピンクのTシャツがスミクロに分類された |
| 帯の最頻色（量子化） | 帯の位置が固定なので、バストアップと全身で胴体を外す |

**必要なのは「色ごとに1枚」だけ（48枚）なので、コンタクトシートから目視で選ぶ方式に切り替えた。**
自動分類より確実で、枚数も現実的。

### 選定基準

- 同じモデル・同じセット・同じ引きで色を揃える（横に並べたとき色だけが変わって見える）
- 正面・全身寄り
- 犬商品は同じ犬種・同じポーズを優先

### 切り出し

9/30に確立した規則をそのまま使う。

1. 頭部の肌色検出で**頭の中心を実測**
2. `left = 頭の中心 × 画像幅 − 窓幅 ÷ 2`（頭の中心を画像の中心に）
3. 縦は 頭頂が上から5%、服の裾が86%
4. 比率 5:6（テーマが `object-fit: fill` なので比率がずれると歪む）

## 4. テーマ側の実装方針（未着手）

`sections/collection-template.liquid` のループを、商品ごとではなく**色ごと**に回す。

```liquid
{% for product in collection.products %}
  {% assign ci = 色オプションのindex %}
  {% if ci == nil %}
    {% include 'product-grid-item' %}          ← 色なし商品はそのまま1枚
  {% else %}
    {% for c in 色の一覧 %}
      {% if その色に販売可能な在庫がある %}      ← 完売色は出さない
        {% assign featured = product %}
        {% assign card_variant = その色の最初の購入可能バリエーション %}
        {% include 'product-grid-item-color' %} ← 画像とリンクをその色に差し替え
      {% endif %}
    {% endfor %}
  {% endif %}
{% endfor %}
```

注意点:

- 2026-09-23まで入っていた旧アプリ（eosh）のハックは、バリエーションIDを
  **区切りなしで連結した文字列に `contains` で部分一致**させていたため誤爆していた。
  今回はIDの完全一致で組む
- カード名に色を付ける（`商品名 / ピンク`）
- リンクは `?variant=<その色の購入可能なバリエーションID>`
- ページネーションは商品単位（20件）のままなので、1ページのカード数は20〜45枚で変動する
- **公開はユーザー操作。** テーマ公開はMCPの安全ポリシーでブロックされる

## 5. テーマ実装（下書きテーマで動作確認済み）

### 追加/変更したファイル（3つ）

| ファイル | 役割 |
|---|---|
| `snippets/sumif-collection-item.liquid` | 商品1件を、色ごとのカードに展開する（新規） |
| `snippets/sumif-color-card.liquid` | 色別カード1枚の描画（新規） |

原本は `docs/data/theme-color-split-2026-09-30/` に保存。

### 実装の要点

- 色オプション名は `色` / `カラー` / `color` / `colour` を認識
- **購入可能なバリエーションがある色だけ**を集める → 完売色は自動でカードが出ない
- カード画像は `card_variant.featured_image`（無ければ商品の1枚目にフォールバック）
- リンクは `商品URL?variant=<その色の購入可能な最初のバリエーションID>`
- 色オプションがない商品（Various dogs 3点）は従来どおり `product-grid-item` で1枚
- **判定は色名の完全一致。** 旧アプリのようなID連結＋部分一致はしていない

## 6. カード下の表示を整理（2026-09-30）

ユーザー指示: 提案1・2・3すべて実施。

### 訂正: 色の文字が小さくなっていなかった

「色は小さめになってる？」という指摘を受けて実測したところ、**ほぼ効いていなかった。**

| | 指摘時 | 修正後 |
|---|---|---|
| 商品名 | 12.6px / 700 | 12.6px / 700 |
| 色 | **12.04px**（商品名比 −4%） | **10.5px**（商品名比 −17%） |
| 価格 | 10.5px | 10.5px |

原因: `font-size: .86em` の基準が商品名(12.6px)ではなく**親要素の14px**だったため、
12.04px にしかならず、価格(10.5px)より大きかった。

`.75em` に変更し、価格と同じ 10.5px に揃えた。opacity も .62 → .60。

**見た目の指摘は必ずブラウザで計算値を測ってから「直った」と言うこと。**
スクリーンショットの目視では4%の差は分からない。

なお色の行だけフォントが `system_ui`（商品名・価格は `Jost`）だが、
色名はすべてカタカナで Jost に日本語グリフが無くフォールバックするため、見た目の差は出ない。
