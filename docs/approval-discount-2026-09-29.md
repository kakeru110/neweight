# 承認制割引の可否と設計（2026-09-29）

ユーザー要望:
> 承認によった割引きを実施したいが可能？ → 承認した人だけが使える割引

**結論: 可能。Shopify Basic プランのままできる。**
ただし、調べた結果**当初考えていた作り方は使えない**ことが分かった。

---

## 1. 訂正: 無期限の割引コードは、すでに全部止まっている

`docs/discount-timing-2026-09-28.md` に「5件がACTIVE」と書いたが、
**2026-09-29時点で5件すべて `EXPIRED`**。

| コード | 率 | 終了日時 |
|---|---:|---|
| `tamarusama` | 20% | 2026-09-28 13:49:12 |
| `kazokuwari` | 40% | 2026-09-28 13:49:20 |
| `sumifsyawari` | 60% | 2026-09-28 13:49:25 |
| `sumifwari` | 20% | 2026-09-28 13:49:32 |
| `XTZE3J1CRFFC` | 15% | 2026-09-28 13:49:39 |

終了日時が **30秒以内に揃っている**ので、ユーザーが9/28にまとめて処理したもの。
**現在、有効な割引は1件もない。** 承認制を始める前提は整っている。

---

## 2. 🔴 設計が変わる事実: 顧客の約87%はアカウントが無効

Shopifyには「特定の顧客だけが使える割引」「顧客セグメント限定の割引」があり、
Basicプランでも使える。これが承認制の本命に見える。

**しかしこの方式は、お客様がログインした状態で決済しないと適用されない。**

| | |
|---|---:|
| 顧客総数 | 419件 |
| サンプル取得分のうち **アカウント有効（ENABLED）** | 31件（**約13%**） |
| アカウント無効（DISABLED＝ゲスト購入） | 約87% |

このストアのお客様はほぼ全員ゲスト購入。
顧客限定割引にすると、**承認した人にアカウント作成とログインを強制する**ことになる。
365日で9件しか注文がない状況で、決済前に1ステップ増やすのは割に合わない。

→ **顧客限定・セグメント限定は採らない。**

---

## 3. 採用する方式: 承認した人ごとに「1回だけ使える個別コード」を発行

| 設定 | 値 | 理由 |
|---|---|---|
| コード | 承認した人ごとに個別（例 `SUMIF-AP-0001`） | コードそのものが承認の証になる |
| `usageLimit` | **1** | 全体で1回しか使えない。漏れても1件で止まる |
| `appliesOncePerCustomer` | true | 二重適用の防止 |
| `customerSelection` | 全顧客 | **ログイン不要**にするため。制限はコード側でかける |
| `endsAt` | 発行から2週間程度 | 放置された承認が生き続けるのを防ぐ |

ログインを求めずに「承認した人だけ」を実現できる。
漏洩リスクは `usageLimit: 1` と期限で封じ込める。

### 継続取引（卸・リピーター）の場合だけ例外

同じ人が何度も使う必要があるなら、顧客限定＋ログインが必要になる。
その場合はアカウント作成を案内する前提で組む。
なお **Shopify標準のB2B（法人アカウント・会社別価格表）は Plus 限定**で、
Basicでは使えない。卸を本格化するならアプリ導入か、Shopify外での請求書対応になる。

---

## 4. 決まっていないもの（これが決まれば発行できる）

| 項目 | 状態 |
|---|---|
| **割引率** | 未定。旧コードは60%/40%だった |
| **対象商品** | 未定。全品か、夏物556点（¥3,253,000）だけか |
| **有効期間** | 未定（推奨：発行から2週間） |
| 想定する相手 | 未定（卸／インフルエンサー／既存顧客／イベント） |

`docs/cash-and-inventory-2026-09-28.md` の方針では
**夏物は捌く・秋冬は定価**としている。承認制割引を夏物に限定すれば、
その方針と矛盾せずに現金化を進められる。

率は原価が分からないと下限が出せない（`unitCost` が全件 null）。
**キャッシュ優先なら原価割れも選択肢**とユーザーが明言しているため、
率は原価ではなく「いくら現金が要るか」から逆算するのが筋。

---

## 5. 発行の手順（率が決まり次第、実行できる）

1. `discountCodeBasicCreate` で1人1コードを発行（上の設定）
2. 発行したコード・相手・期限を `docs/data/` に記録
3. 使用状況は `asyncUsageCount` で追える
4. 期限切れは自動。手動で止めるなら `discountCodeDeactivate`
